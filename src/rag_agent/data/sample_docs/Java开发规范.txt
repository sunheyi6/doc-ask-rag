Java 开发规范（内部版）
======================

一、命名规范
----------
1. 类名：大驼峰命名法（PascalCase），如 UserService、OrderController
2. 方法名：小驼峰命名法（camelCase），如 getUserById、saveOrder
3. 常量：全大写加下划线，如 MAX_RETRY_COUNT、DEFAULT_TIMEOUT
4. 包名：全小写，域名倒序，如 com.example.etq.common

二、代码风格
----------
1. 缩进统一使用 4 个空格，禁止使用 Tab
2. 每行代码不超过 120 字符，超长需换行并对齐
3. 方法体不超过 80 行，超过应拆分为多个私有方法
4. 魔法数字必须定义为常量，禁止散落硬编码

三、异常处理
----------
1. 禁止捕获 Exception 后吞掉异常，必须记录日志
2. 业务异常使用自定义异常类 BizException，统一在全局异常处理器捕获
3. 不允许在循环中 catch 异常，应先做参数校验
4. 调用外部接口（如数据库、Redis）必须设置超时时间

四、安全规范
----------
1. SQL 禁止字符串拼接，必须使用 PreparedStatement 参数化查询
2. 用户输入必须做校验与转义，防止 SQL 注入与 XSS 攻击
3. API 接口必须校验登录态与权限，禁止越权访问
4. 日志中禁止打印明文密码、Token 等敏感信息

五、提交规范
----------
1. 每次提交只包含一个逻辑变更，提交信息格式：类型(模块): 描述
2. 类型包括：feat、fix、docs、refactor、test、chore
3. 合并代码前必须通过全部单元测试与代码评审
